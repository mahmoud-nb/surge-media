<Section
  id="transformations"
  eyebrow="On-the-fly transformations"
  title="Every size, every format. One URL away."
  lead="Upload the original once. surgeMedia generates the variant your page asks for on the first request, keeps it, and serves it with immutable cache headers from then on."
>

<Tabs syncKey="showcase">
<TabItem label="Responsive HTML" icon="seti:html">

```html
<picture>
  <source type="image/avif" srcset="https://media.example.com/m/k7d2m9qz/v3/w_800,h_450/hero.avif" />
  <source type="image/webp" srcset="https://media.example.com/m/k7d2m9qz/v3/w_800,h_450/hero.webp" />
  <img src="https://media.example.com/m/k7d2m9qz/v3/w_800,h_450/hero.jpg"
       width="800" height="450" alt="Our new collection" />
</picture>
```

</TabItem>
<TabItem label="URL anatomy" icon="seti:default">

```text
https://media.example.com/m/k7d2m9qz/v3/w_800,h_450,g_focal,q_70/hero.avif
                            └──┬───┘ └┬┘ └─────────┬──────────┘ └──┬─────┘
                            media id  version   transformation   name.format
```

- **`w_` / `h_`** set the size, **`fit_`** the strategy (`cover`, `contain`, `inside`…), **`g_focal`** keeps the subject in frame.
- **The extension is the format**: `jpg`, `png`, `webp` or `avif`. Images are never upscaled and metadata (EXIF, GPS) is stripped.
- **Presets** (the built-in `preview`, or your own like `card` or `og-image`) freeze a transformation under a name. A project can also accept only presets, or only signed URLs.

</TabItem>
<TabItem label="From the API" icon="seti:json">

```json
// GET /api/v1/projects/{projectId}/media/{mediaId}
{
  "id": "k7d2m9qz",
  "kind": "image",
  "width": 4032,
  "height": 3024,
  "altText": "Our new collection",
  "focalPoint": { "x": 0.62, "y": 0.4 },
  "urlTemplate": "https://media.example.com/m/k7d2m9qz/v3/{transform}/hero.{format}"
}
```

Fill in `{transform}` and `{format}` client-side to build any `srcset` — no extra request.

</TabItem>
</Tabs>

<Section
  id="install"
  eyebrow="Installation"
  title="Install it your way"
  lead="One npm package, one Docker image. Pick the database that fits today — switch to PostgreSQL or MySQL when you grow."
>

<Tabs syncKey="install">
<TabItem label="npm / npx" icon="npm">

```bash
# In the folder that will hold your configuration and data (Node.js 24+)
npm install @surge-media/core
npx surge-media init    # choose SQLite, PostgreSQL or MySQL / MariaDB
npx surge-media start   # admin, API and delivery on http://localhost:3000
```

</TabItem>
<TabItem label="Docker" icon="seti:docker">

```bash
docker run -d --name surge-media -p 127.0.0.1:3000:3000 \
  -v surge-media-data:/app/data \
  -e NUXT_SITE_URL=https://media.example.com \
  -e NUXT_BOOTSTRAP_ADMIN_EMAIL=you@example.com \
  -e NUXT_BOOTSTRAP_ADMIN_PASSWORD='a-long-passphrase' \
  ghcr.io/mahmoud-nb/surge-media
```

</TabItem>
<TabItem label="Compose + PostgreSQL" icon="seti:config">

```bash
# Web server + video worker + PostgreSQL 17, from the repository's docker/ folder
POSTGRES_PASSWORD='change-me' docker compose -f docker/compose.postgres.yaml up -d
```

</TabItem>
</Tabs>
