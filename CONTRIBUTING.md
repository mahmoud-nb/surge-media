# Contributing to surgeMedia

Thank you for your interest in surgeMedia. Bug reports, ideas, documentation fixes and pull requests are all
welcome.

## Reporting a problem or suggesting a feature

- **Security issue**: never in a public issue. Follow the [security policy](SECURITY.md) (private reporting
  through GitHub).
- **Bug**: open an [issue](https://github.com/mahmoud-nb/surge-media/issues) with the version, how you installed
  surgeMedia (npm package or Docker image), what you did, what you expected and what happened. Attach the report of
  `npx surge-media diagnose` ([setup.md § 17.1](setup.md#171-diagnostic-report)): it contains no secret and no
  personal data, but read it before posting.
- **Feature request**: open an issue describing the need first, before any code: a short discussion avoids work
  that would not fit the project.

## Proposing a change

1. For anything beyond a small fix, open or comment on an issue first.
2. Fork the repository and create a branch from `main`.
3. Set up the project ([setup.md § 18](setup.md#18-developing-surgemedia)): Node.js 24, pnpm 12, then
   `pnpm install`, `pnpm db:init` and `pnpm dev`.
4. Make your change, with tests for any rule or behaviour it introduces.
5. Run the checks that continuous integration runs:

   ```bash
   pnpm lint
   pnpm typecheck
   pnpm test
   pnpm i18n:check        # every interface and CLI text exists in French and English
   pnpm a11y:contrast     # theme colours meet WCAG 2.2 AA
   pnpm --filter @surge-media/core db:migration --check   # migrations match the Prisma schema
   ```

6. Open a pull request that explains what changes and why, and links the issue.

Keep pull requests focused: one change per pull request is easier to review and to revert.

## Conventions

- **Commit messages** follow [Conventional Commits](https://www.conventionalcommits.org) (`feat`, `fix`, `perf`,
  `docs`, `refactor`, `test`, `build`, `ci`, `chore`…), checked by commitlint: they feed the changelog and the
  version number.
- **TypeScript** in strict mode; ESLint sets the style (`pnpm lint:fix` fixes most of it).
- **Interface texts** go through the translation files, in French and English; no hard-coded text.
- **Accessibility**: new screens and components target WCAG 2.2 AA (keyboard, labels, contrast, announced states).
- **Database changes** come with a migration for each provider (SQLite, PostgreSQL, MySQL), generated by
  `pnpm --filter @surge-media/core db:migration <name>`; published migrations are never edited.
- **New environment variable**: document it in `apps/core/.env.example` and [setup.md](setup.md), and classify it in
  `apps/core/cli/lib/diagnose/variables.ts` (a test fails otherwise), so that `surge-media diagnose` never prints a
  secret.
- **Dependencies**: add one only when it is clearly worth it; `pnpm security:audit` must stay clean.

Before your first pull request can be merged, you are asked to accept the surgeMedia **Contributor License
Agreement** (CLA). A bot comments on the pull request with a link to the agreement; accepting it takes one click

the rest of these libraries.

## Behaviour

Be respectful and constructive in issues, pull requests and reviews. Harassment or abuse of any kind is not
accepted; the maintainers may remove such content and block its authors.
